# Free plan, trial claim, and connect

Cutover runbook: `docs/free-plan-attested-sessions.md`. Pricing unit reference: `docs/item-based-pricing.md`.

## Free-plan tier (no-signin via MCP)

- The console GraphQL endpoint also accepts requests with header `X-Free-Plan-Session` and no `Authorization`. Resolved at `src/lib/free-plan-context.ts` by the **async** `isFreePlanRequest`, which takes two forms: a **signed session/workspace token** we issued (`src/lib/free-plan-session-token.ts`, HS256 under `FREE_PLAN_NAMESPACE_SALT`, audience `graffiticode-session`, 48h) whose payload namespace is authoritative, or a **raw uuid** hashed on arrival. The raw form is self-asserted and therefore forgeable — it is accepted only until `FREE_PLAN_REQUIRE_SIGNED_SESSION=true`, after which the MCP `initialize` endpoint is the sole way to obtain a session (and the only place worth rate-limiting at the Cloudflare edge; the raw client IP is never read in-app).
- Free-plan requests resolve to `auth.uid` = the FREE_PLAN_API_KEY's owner uid. Items are tagged `freePlan: true`, `sessionNamespace`, and `expiresAt` (48h TTL).
- **`sessionNamespace` means WORKSPACE, not "the session that created this."** An MCP session is an in-memory transport binding that dies on restart/scale-out and that ChatGPT re-mints *per tool call*, so it is a bad owner for an item that outlives it. What a client does re-present is the item id (already treated as a capability — see `isItemVisibleToFreePlan`'s `byId` branch), so a **mutation** on an existing item rebinds the caller to that item's workspace (`adoptWorkspace`); reads never adopt. The console returns a signed `workspace` handle on item responses, which the MCP server presents thereafter.
- **Metered in ITEMS, not dollars or compiles** — same unit as the paid tiers (`docs/item-based-pricing.md`). Three limits: **5 revisions per item** (`trialRevisions` on the item doc, counted on successful content change so a failed generation never burns one, gated in `generateCode` where the spend happens — not in `updateItem`, which runs after); a **monthly budget inherited from the trial account's own subscription** (it is a real account; `overageLimitItems: 0` turns `checkItemCreateAllowed`'s paid branch into a hard cap — `scripts/cap-trial-account.ts`); and a **derived daily allowance**, `ceil(remaining ÷ days left in the billing period)`, which self-balances and never goes dark mid-period (`src/lib/free-plan-quota.ts`). Trial items are **counted but never invoiced** — `recordBillableItem` runs the `usage` write and `currentMonthTotal` increment, then returns before the Stripe meter.
- Burst limiters (`src/lib/free-plan-throttle.ts`, `BURST`) are runaway-loop guards, **not** the budget: generation 5/60s, all-GraphQL 120/60s, compile proxy 30/60s. The API ceiling must clear `get_item`'s long-poll (~18 requests from one tool call) or the first item a new user creates breaks.
- Language scope (`freePlan?: boolean` in `src/lib/languages.ts`) ships **inert** — with nothing marked, the gate is a no-op; enabling is a data change, not a release.
- The browser console UI requires real sign-in; free-plan is hosted-only via the MCP server.
- Env vars: `FREE_PLAN_API_KEY`, `FREE_PLAN_NAMESPACE_SALT`, optional `FREE_PLAN_REQUIRE_SIGNED_SESSION`, `FREE_PLAN_ITEM_REVISION_LIMIT`, `FREE_PLAN_BURST_LIMIT`, `FREE_PLAN_API_BURST_LIMIT`, `FREE_PLAN_COMPILE_BURST_LIMIT`, `FREE_PLAN_BURST_WINDOW_SECONDS`. Pushed via `scripts/set-free-plan-secrets.sh` from `.env.local` to Secret Manager + mounted on Cloud Run.
- Cost telemetry only (never a control): `src/lib/model-pricing.ts` has a per-model rate table — the old code applied Sonnet rates to every model, understating Opus by 1.67× — and writes to `free-plan-state/spend-{YYYYMMDD}`, which `scripts/mcp-funnel-report.ts` reads for cost-per-acquired-account.

## Trial-claim flow (`/claim?token=<jwt>`)

The **console** mints a 24h HS256 JWT signed with `FREE_PLAN_NAMESPACE_SALT` (audience `graffiticode-claim`, payload `{ sessionNamespace, sessionUuid }`) and returns it as `claimToken` on the GraphQL `Item`; the MCP server surfaces it as `claim_url` (with `&src=chat` for footer-vs-chat attribution and `&agent=<host>` for the connect step below) rather than minting its own. **The MCP server used to mint it from its transport session uuid, which was wrong for any client whose session isn't where its items live** — a stateless client revising an item created in an earlier session got a token addressing an empty namespace, so claiming transferred zero items. Only the console knows the effective (post-adoption) workspace. `createItem`/`updateItem` also return a signed `workspace` handle; `getItem` returns `claimToken` only (seeing an item may let you save it; it must not enroll you in its workspace). The console `/claim` page renders `<AuthMethodDialog variant="claim">`; on successful sign-in (email or wallet) it calls the `claimFreePlanSession(token)` GraphQL mutation. The resolver verifies the JWT via `src/lib/claim-token.ts`, queries `users/{trialUid}/items` matching `freePlan==true && sessionNamespace==X && expiresAt>now`, and copies each into the authenticated user's `users/{uid}/items/` collection with `taskId: null`, `code` preserved, `app: 'console'` (force-overridden so claims appear in the default `/items` view), free-plan flags cleared, and `claimedFrom: sessionUuid` plus `claimedFromNamespace` for provenance (the namespace is recorded explicitly rather than left to be re-derived by hashing `claimedFrom` — with workspace adoption the token's uuid is whichever session presented it, so re-hashing yields the wrong namespace and the funnel report loses the join). The claim resolver prefers fetching `code` **fresh from api.graffiticode.org via trial auth** (`getApiTask({ id: data.taskId, auth: trialAuth })`) over trusting the stored `data.code`, so claims still produce correct content even if the Firestore copy went stale. Tasks lazily re-post under the new uid on first read via the existing guards in `getItems`/`getItem` (precondition: `createItem` AND `updateItem` both persist the parsed AST as `code` on the Firestore item doc whenever taskId changes — required because tasks on api.graffiticode.org stay owned by the trial uid; the lazy repost is what relocates them). For local testing, mint a JWT via `npx tsx scripts/mint-claim-token.ts <sessionUuid>`.

## After the claim, the connect step

Claiming saves the items but leaves the *agent* anonymous — its next `create_item` lands back in a trial workspace with another claim link, and since claiming copies rather than moves, the agent keeps editing the anonymous originals while the account holds divergent copies. So `/claim` no longer hard-navigates into the editor on success; it shows "Saved N items" → `<ConnectAgentInstructions>` → "Open item" (still `window.location.assign`, for the sign-in-remount reason documented in `claim.tsx`). Instructions are keyed by the `agent` bucket, which is **stashed in sessionStorage** exactly like the token — the sign-in remount empties `router.query`. It is `agent=` and not `client=` because `_app.tsx` already consumes `?client=` app-wide as the item source surface. Hosts whose config takes an `Authorization` header (`claude-code`, `editor`, `unknown`) get a copy-paste snippet plus a **Create an API key** button reusing `client.apiKeys.create` (same path as `APIKeysCard`), beaconed with `source: 'claim'` so key creation from this screen is separable from Settings; `claude-app`/`openai` connector UIs have no header field, so they are told plainly that items stay anonymous there rather than promised a sign-in that `/oauth/consent` (Google-only today) can't yet give them. The MCP server owns the bucket taxonomy; an unknown value degrades to `unknown` + a manual host picker, so the two repos can deploy in either order.
